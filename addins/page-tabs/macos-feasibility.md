# MoreTabs on native OneNote for Mac

**Decision, November 25, 2026.** Most of the MoreTabs interface can be rebuilt on macOS. A public, supported way to reproduce its complete behavior inside the shipping Mac OneNote editor has not been established. The largest gaps are reserving space inside a particular window, identifying and navigating the page in that window, and adding a command to OneNote’s own page menu. These findings come from the Windows implementation, Microsoft and Apple documentation, and published Mac integrations. No Mac OneNote build was exercised in this assessment.

## What the Windows port would lose

The Windows prototype calls `Window.CurrentPageId` and `Window.NavigateTo` on the editor it has bound. It asks OneNote for the Quick Notes destination, reserves real space by moving the native document window, and uses a separate COM helper to extend OneNote’s menus. Microsoft documents COM add-ins as Windows-only. Its OneNote Office.js platform table lists only Office on the web. Apple’s extension framework also requires an extension point supported by the host. Switching the UI to Swift would replace the renderer, but none of those host connections. ## Parity by feature

| Windows behavior | Mac assessment |
| --- | --- |
| Persistent cross-notebook tabs, duplicate tabs for one page, close, pin tabs and notebook groups, bookmarks, configurable Home, tool visibility, overflow, and restore after restart | MoreTabs owns this state. A native companion can implement these behaviors and reuse the existing artwork. Give each tab its own identity and store its destination separately so two tabs can follow the same page independently. [Working-set implementation](prototype/WorkingSet.cs) |
| Same three pickers for new tab, Home, and new-note destination, including nested section groups and subpages | Graph exposes notebooks, section groups, sections, pages, and page indentation and order. A picker for the signed-in cloud account is feasible. Whether it exactly matches the notebooks open in the local Mac client, their order, additional accounts, and unsynced changes is a separate question. [Graph OneNote overview](https://learn.microsoft.com/en-us/graph/api/resources/onenote-api-overview?view=graph-rest-1.0) · [Hierarchy and page levels](https://learn.microsoft.com/en-us/graph/onenote-get-content) |
| Click a tab, bookmark, or Home to open its page in the associated editor | Graph supplies a native client URL for a page. Its documented link has no destination-window parameter. With two OneNote windows open, delivery to the intended window needs proof. A second approach is to target that window’s accessible navigation controls and select the page there. Microsoft documents navigating those controls with VoiceOver. [Client links](https://learn.microsoft.com/en-us/graph/open-onenote-client) · [Mac navigation and focus](https://support.microsoft.com/en-us/accessibility/onenote/use-a-screen-reader-to-explore-and-navigate-onenote) |
| Follow OneNote’s own navigation and page renames while retaining the active tab, including Back and Forward | Microsoft documents a current-page property on Windows. I found no corresponding public Mac per-window page ID or page-change event. Accessibility can report observations the app exposes. A row title alone is ambiguous when two pages have the same name. A Mac implementation must bind the event to the correct window and durable page and verify native history and editor focus. | Create a Quick Note or a page in a chosen section, then focus it in a new tab | Graph supports creating a page by section ID and in the default section of the default notebook. Verify that the latter matches the user’s actual Quick Notes destination. Page creation, desktop sync, routing to the intended window, and focus in the new editor are separate steps. Graph requires a network connection and delegated account access. Exact color matching, including recoloring while running, needs an on-device source. ## Evidence from shipping Mac tools

Hookmark reports that it implemented OneNote page-link capture using UI scripting. Gem Menu advertises bookmarking the current OneNote page and reopening it from the macOS menu bar. These are precedents for an explicit **Keep current page** command. Neither vendor demonstrates a continuously synchronized, space-reserving strip inside OneNote. A companion could start with desktop links and local storage alone. Graph becomes relevant for the account-wide picker and creating pages without driving the UI. [Hookmark integration release](https://discourse.hookproductivity.com/t/hookmark-integration-v-247-is-now-available-with-support-for-microsoft-onenote-mac-app-links/6109) · [Gem Menu for Mac](https://onenotegem.com/m-viewsoftware-640.html)

## First Mac experiment

Record the macOS version, OneNote build, hardware, display scale, and account type. Use two disposable notebooks, three pages, two identically titled pages, and two open OneNote windows. Use Accessibility Inspector to identify what the installed build exposes. Check its scripting dictionary too. macOS requires user-granted Accessibility access for UI scripting. [Apple’s UI scripting guide](https://developer.apple.com/library/archive/documentation/LanguagesUtilities/Conceptual/MacAutomationScriptingGuide/AutomatetheUserInterface.html) · [Apple’s scripting terminology guide](https://developer.apple.com/library/archive/documentation/LanguagesUtilities/Conceptual/MacAutomationScriptingGuide/AboutScriptingTerminology.html)

1. **Prove placement first.** Try to reserve a narrow row below the Mac ribbon and then along the bottom edge. Record the editor and navigation bounds before and after. Pass only if those bounds yield real space, the exposed controls still accept clicks, and the row stays visible and aligned during a drag, ribbon collapse, Preferences, full screen, and a move to a second display. Covering the editor or shrinking the entire OneNote window to park a second window outside it is a companion layout.
2. **Prove window and page identity.** From a tab bound to window B, select three pages across the two notebooks while A is frontmost. Verify B displays the selected page and A keeps its page. Then use OneNote’s own sidebar, link, Back, Forward, and rename actions. Verify that only B’s active tab follows, even for duplicate titles and after restarting. Check that observing navigation does not steal typing focus or overwrite copied text.
3. **Prove the remaining integrations.** Control-click an unselected page B while A is active and verify the new-tab command targets B without replacing A. Create one page in Quick Notes and one in a configured nested section. Check each destination, tab focus, native colors, and what still works with networking disabled. Treat caret, selection, and scroll restoration as exploratory on both platforms.

**Recommendation.** Fund the placement and identity experiment before a Mac UI port. If either gate fails, offer a separately docked companion only as an explicit product choice. If the requirement is to use the existing Windows experience from Mac hardware, Microsoft’s Windows App can connect a Mac to a Windows PC running MoreTabs. That preserves the Windows editor and avoids a second implementation. [Windows App connection options](https://learn.microsoft.com/en-us/windows-app/get-started-connect-devices-desktops-apps)
